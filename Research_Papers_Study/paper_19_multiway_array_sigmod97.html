An Array-Based Algorithm for Simultaneous Multidimensional Aggregates

Yihong Zhao, Prasad Deshpande, Jeffrey F. Naughton (SIGMOD 1997)

⏱️ Focus: 15:00
1. The Core Architecture Insight

Why Tables Waste 80% of Memory for OLAP Aggregations

Traditional Relational OLAP (ROLAP) stores data as rows: (DimensionA_ID, DimensionB_ID, DimensionC_ID, Sales_Amount). Every row has massive metadata overhead, needs B-Tree indexes, and suffers from row-major disk scan bottlenecks.

🧱 The Multidimensional Array (MOLAP) Breakthrough: Instead of storing row IDs, store data directly in an N-dimensional matrix Array[A, B, C] = Sales. The position in the array implicitly tells you the dimensional coordinates! Zero index overhead!

Zhao, Deshpande, and Naughton (SIGMOD 1997) solved the two biggest problems of MOLAP: 1. Gigantic Sparsity: Using Array Chunking with offset compression. 2. Computing All Cuboids Simultaneously: Using single-pass MultiWay Array Aggregation.
2. Mathematical Formalism

Array Chunking & The Minimum Memory Sweep Rule

If an array is $1000 \times 1000 \times 1000$, standard row-major traversal makes accessing columns or depths incur terrible disk thrashing. Zhao et al. divide the array into small hypercube chunks of size $c_A \times c_B \times c_C$ so that any block fits neatly into CPU cache/RAM.

Order of Dimension Sweeping Heuristic:
Order dimensions such that Cardinality(A) ≤ Cardinality(B) ≤ Cardinality(C).

When reading chunks along C, then B, then A:
• Plane (A, B) requires only: 1 chunk buffer in memory!
• Plane (A, C) requires: (Chunk_A) × (Total_C) buffer cells.
• Plane (B, C) requires: (Chunk_B) × (Total_C) buffer cells.
Summing these buffers proves that putting the smallest dimension FIRST minimizes total RAM required!
Projection Plane Buffer Needed During Chunk Sweep When Can Buffer Be Flushed to Disk?
Plane AB 1 Chunk (size $c_A \times c_B$) Flushed every time a full sweep along dimension C finishes!
Plane AC 1 Row of Chunks ($c_A \times |C|$) Flushed every time a full sweep along dimension B finishes.
Plane BC Full Plane Slice ($c_B \times |C|$) Kept until the entire chunk plane finishes.

4. Active Retention Quiz

Test Your Understanding

1. Why does Zhao et al.'s dimension ordering heuristic sort dimensions by $|A| \le |B| \le |C|$?

Explanation: Correct! The buffer for the last plane is proportional to the size of earlier dimensions. Keeping the smallest cardinality dimension first guarantees the smallest total memory footprint.

2. How does MultiWay solve the problem of sparse arrays where 95% of cells are empty?

Explanation: Correct! Empty cells within a chunk are not explicitly stored; only (offset, value) pairs are retained, making sparse arrays highly compact.

3. How many times does MultiWay Array Aggregation scan the underlying data?

Explanation: Correct! The whole power of MultiWay is computing all cuboids simultaneously in a single scan through the chunked array.

4. What is the fundamental difference between ROLAP and MOLAP storage?

Explanation: Correct! MOLAP indexes cells implicitly through array mathematics rather than storing repeated dimension foreign keys.

5. Can MultiWay Array Aggregation compute Iceberg Cubes directly with Apriori pruning?

Explanation: Correct! MultiWay computes all cells in parallel and cannot prune sparse sub-branches. BUC (Beyer & Ramakrishnan 1999) was specifically created to solve this limitation for iceberg cubes.
