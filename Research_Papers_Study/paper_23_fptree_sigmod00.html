Mining Frequent Patterns without Candidate Generation

Jiawei Han, Jian Pei, Yiwen Yin (ACM SIGMOD 2000)

⏱️ Focus: 15:00
1. The Death of Candidate Generation

Why Apriori Chokes on Long Frequent Patterns

If a database contains a frequent pattern of size 100 (e.g. 100 genes in bioinformatics), Apriori must generate $2^{100} - 1 \approx 10^{30}$ candidate itemsets level-by-level, scanning the database 100 times. Even on a supercomputer, Apriori will not finish before the sun explodes.

🥨 The Beginner's Analogy: Apriori searches for words in a book by testing all 2-letter combos, then all 3-letter combos, reading the entire book every time. FP-Growth is like an English dictionary: it builds a prefix tree where common word beginnings share branches. You read the book only twice, compress it into an FP-tree, and mine patterns in memory without generating a single candidate!

3. Theoretical Deep-Dive

The Divide-and-Conquer Magic: 3 Steps

Step 1: Prefix Path Collection (Conditional Pattern Base)

For item $i$, traverse its side-links from the header table across the entire tree. For each node, follow its parent pointers up to the root, recording the prefix path and the node's count.

Step 2: Conditional FP-Tree Construction

Treat the prefix paths as transaction logs and sum item counts. Filter infrequent items (< minsup). Rebuild a small, local tree containing only frequent prefix items.

Step 3: Single-Path Optimization

If a conditional FP-tree has only a single branch with $k$ items, you do NOT need recursion! Enumerate all $2^k - 1$ combinations directly in constant time.

4. Midsem Practice Quiz

Exam Retention Check

Q1. How many complete database disk scans does the FP-Growth algorithm require?

Correct! FP-Growth scans the raw database exactly TWICE. After building the in-memory tree in Scan 2, all pattern extraction occurs in main memory without any further disk I/O.
5. Active Retention Quiz

Test Your Understanding

1. How many full database scans does FP-Growth perform?

Explanation: Correct! After building the FP-Tree in 2 passes, all frequent patterns are mined directly from memory without ever touching the disk.

2. In what order must items within each transaction be inserted into an FP-Tree?

Explanation: Correct! Sorting by descending frequency maximizes prefix sharing among transactions, compressing the tree.

3. What is a Conditional Pattern Base for item X?

Explanation: Correct! The prefix paths leading to X represent the sub-database conditioned on the presence of item X.

4. What is the role of the Header Table in an FP-Tree?

Explanation: Correct! The header side-links allow immediate traversal of all occurrences of an item without searching the entire tree.

5. What optimization applies when a conditional FP-Tree consists of a single linear path?

Explanation: Correct! A single branch allows direct combinatorial power-set enumeration.
