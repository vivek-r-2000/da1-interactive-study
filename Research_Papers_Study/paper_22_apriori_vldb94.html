1. The Retail Nightmare

Finding Hidden Shopping Habits in Billions of Transactions

In 1994, supermarkets had point-of-sale barcode scanners recording millions of shopping baskets. If a supermarket carries 10,000 items, the number of possible item combinations is $2^{10,000}$—an unfathomable number larger than all atoms in the universe. Testing every combination is impossible.

🥨 The Beginner's Analogy: If nobody in your town buys anchovies, can {Bread, Milk, Anchovies} be a popular combination? Absolutely not! Every basket containing Bread, Milk, and Anchovies ALSO contains Anchovies. If Anchovies fails the popularity test on its own, ANY larger basket containing it fails automatically. That is the Apriori Principle.

3. Theoretical Deep-Dive

How Candidate Hash-Trees Accelerate Support Counting

1. Hash-Tree Architecture

Candidates $C_k$ are stored in a tree of depth $k$. At depth $d$, internal nodes contain hash buckets partitioned by hashing the $d$-th item.

Leaf nodes store actual candidate itemsets. When a leaf exceeds max leaf size, it splits into an internal hash node.

2. The Recursive Subset Function

For each transaction $t$ in the database, the algorithm calls subset(node, t). It hashes on every item in $t$, recursively traversing matched branches in $O(\max(k, |t|))$, skipping candidates that don't match.

4. Midsem Practice Quiz

Exam Retention Check

Q1. If {A, B} is frequent and {A, C} is frequent, but {B, C} is INFREQUENT. Can candidate {A, B, C} survive the prune step in apriori-gen?

Correct! In the prune step of apriori-gen, every (k-1)-subset must be in L_{k-1}. Since subset {B, C} is infrequent, candidate {A, B, C} is deleted immediately without checking the database.
5. Active Retention Quiz

Test Your Understanding

1. What is the fundamental anti-monotone property of support in Apriori?

Explanation: Correct! Any transaction containing superset X must also contain subset Y. Therefore Support(X) ≤ Support(Y).

2. In apriori-gen, how are candidate k-itemsets generated in the Join step?

Explanation: Correct! The prefix-matching join ensures candidates are generated without duplicate permutations.

3. What does the Prune step of apriori-gen do?

Explanation: Correct! By the anti-monotone property, if any subset is infrequent, the candidate cannot possibly be frequent.

4. What data structure did Agrawal & Srikant use to count candidate occurrences rapidly within a transaction?

Explanation: Correct! The hash-tree hashes items at each level to quickly identify which candidates are contained in a transaction.

5. How many database scans does Apriori make if the longest frequent itemset has length K?

Explanation: Correct! Each pass k scans the database to count support for candidate k-itemsets.
