🌍 What is Classification? • Card 1 of 44
🐱🐶 Teaching a Computer to Sort Things into Buckets

Imagine teaching a young child to tell cats from dogs. You show them 1,000 labeled pictures — "this is a cat", "this is a dog" — over and over again. Slowly the child picks up the rules: cats have pointy ears, dogs have floppy ears, cats are smaller…

After training, show the child a brand-new picture they've never seen. They can correctly identify the animal! This is exactly how a classification algorithm works.

👉 You feed it labeled examples → it learns a model → it predicts labels for new, unseen data.

Why does this matter? Classification powers spam filters, medical diagnosis, image recognition, credit scoring, and fraud detection — basically every "yes/no" or "which category?" decision a computer makes.
🌍 What is Classification? • Card 2 of 44
🔄 Two-Step Process: Train, Then Test

Every classification system works in exactly two phases:

  • Step 1 — Training: Feed the algorithm many labeled examples. It learns a model (a set of rules or a mathematical function) that maps inputs → labels.
  • Step 2 — Testing/Inference: Give the trained model new, unlabeled data. It applies what it learned to predict the label.

Think of it like a student cramming for an exam (training) and then sitting the real test (inference). The exam questions are new — the student must generalize.

Key insight: The model is only useful if it generalizes — performs well on data it has never seen before. A student who only memorized exact past questions will fail a new exam. Same with classifiers!
🌍 What is Classification? • Card 3 of 44
🏷️ Supervised vs Unsupervised Learning

Classification is supervised learning — it needs labeled data to train. Each training example comes pre-tagged with the correct answer.

In contrast, clustering (like k-means) is unsupervised — it finds patterns with no labels at all.

  • 🟢 Supervised: "This email is spam." "This tumor is malignant." → Labels provided by humans.
  • 🔵 Unsupervised: "Group these customers somehow." → No pre-existing labels.

Labeled data is expensive — humans must carefully annotate thousands of examples. That's why unsupervised methods are also very valuable in practice.

Why does this matter? Understanding supervised vs unsupervised helps you choose the right tool for a problem — and helps you estimate how much human labeling effort your project needs.

🌳 Decision Trees • Card 6 of 44
🎮 20 Questions: The Original Decision Tree

You've played the game of 20 Questions: "Is it an animal? → Yes. Does it have 4 legs? → Yes. Is it bigger than a dog? → No. Does it meow? → Yes. Is it a cat? → YES!"

Each question splits the possibilities in half. You're building a tree of questions — each branch narrows down the answer until you reach a final decision.

A decision tree does exactly this — it learns which questions to ask and in what order, based on the training data. The smartest first question is the one that splits the data most cleanly.

Why does this matter? Decision trees are one of the most interpretable models. You can actually read the tree and understand why it made a decision — crucial for medicine and law.
🌳 Decision Trees • Card 7 of 44
🏗️ Anatomy of a Decision Tree

Every decision tree is made of three types of nodes:

  • 🌱 Root Node: The very first split — the most important question. Tests a single attribute.
  • 🔀 Internal Nodes: Further splits — more questions that narrow down the answer.
  • 🍃 Leaf Nodes: The final answer — a class label. No more splits here.

Each path from the root to a leaf represents one decision rule. For example: "IF age ≤ 30 AND income = High THEN buys_computer = Yes".

Key insight: The depth of the tree controls complexity. Deep trees can model complex rules but risk overfitting. Shallow trees are simpler and generalize better.

🌳 Decision Trees • Card 9 of 44
📊 Information Gain — Choosing the Best Split

How does the tree know which attribute to split on first? It uses Information Gain.

The idea: every split should make the resulting groups purer — ideally, one group is all "Yes" and the other is all "No". A pure group has low entropy (no uncertainty).

  • 📏 Entropy measures how mixed up a set of labels is (impurity).
  • 📈 Information Gain = Entropy before split − weighted average entropy after split.
  • ✅ Pick the attribute with the highest Information Gain.
IG(D, A) = H(D) − Σ (|Dᵥ|/|D|) × H(Dᵥ)
Intuition: You want splits that tell you the most new information. A split that leaves both halves equally mixed is useless — zero information gain.
🌳 Decision Trees • Card 10 of 44
🍬 Entropy: The Bag of Candies Analogy

Imagine a bag of candies. If the bag has 100% red candies — you're never surprised when you reach in. Entropy = 0 (zero uncertainty).

Now imagine the bag has 50% red and 50% blue — maximum surprise! You have no idea what color you'll get. Entropy = 1 bit (maximum uncertainty).

Entropy measures how "mixed up" or uncertain a dataset is. When we split data, we want the resulting groups to be less mixed up — more like the all-red-candy bag.

H = −p log₂p − (1−p) log₂(1−p)
Memory trick: Think of entropy as SURPRISE. A predictable outcome (all one class) → no surprise → low entropy. A random outcome (50/50 split) → maximum surprise → high entropy.

🌳 Decision Trees • Card 12 of 44
🧮 Gini Index — Another Purity Measure

The Gini Index is an alternative to entropy for measuring impurity. Used by the CART (Classification and Regression Trees) algorithm, including scikit-learn's default.

Gini(D) = 1 − Σ pᵢ²

For a binary problem with classes Yes/No:

Gini = 1 − p² − (1−p)²
  • 🟢 Pure node (100% one class): Gini = 0
  • 🔴 Maximally impure (50/50 split): Gini = 0.5
Entropy vs Gini: Both measure impurity. Entropy uses logarithms (slower) and is slightly more sensitive to imbalanced splits. Gini is faster to compute. In practice, they give very similar results — don't stress too much about which one to use!
🌳 Decision Trees • Card 13 of 44
✂️ Overfitting & Pruning — When Trees Grow Too Deep

If you let a decision tree grow indefinitely, it will eventually create a perfect leaf for every single training example. Training accuracy = 100%!

But this is terrible — the tree has memorized the training data (including random noise and quirks) instead of learning general patterns. It will fail miserably on new data.

Pruning cuts back overfitted branches. Two approaches:

  • 🪓 Pre-pruning: Stop growing the tree early (set max depth, min samples per leaf).
  • ✂️ Post-pruning: Grow the full tree, then remove branches that don't improve performance on a validation set.
Common mistake: Reporting training accuracy without checking test accuracy. Always evaluate on held-out data!
🌳 Decision Trees • Card 14 of 44
⚖️ Underfitting vs Overfitting — The Goldilocks Problem

Finding the right model complexity is the central challenge in machine learning:

  • 🥶 Underfitting (too simple): Tree is too shallow. It misses real patterns in the data. Both training AND test accuracy are low.
  • 🔥 Overfitting (too complex): Tree is too deep. Memorizes training noise. Training accuracy is very high, test accuracy is low.
  • ✅ Just right: Tree captures the real signal without fitting noise. Good accuracy on both training AND test data.

How to find the sweet spot: Use cross-validation. Split data into k folds, train on k-1, test on 1, repeat. Choose the depth that maximizes average test performance.

📧 Naive Bayes • Card 16 of 44
📬 The World's First Spam Filter

Your email inbox has seen 1,000 emails. A human has labeled each one: spam ✉️ or not-spam 📩.

You notice: the word "FREE" appears in 80% of spam but only 5% of real emails. The word "meeting" appears in 60% of real emails but only 2% of spam.

Now a new email arrives. It contains "FREE" and "meeting". What's your best guess — spam or not?

Naive Bayes answers this by calculating the probability of each class given the words, and picking the most likely one. It's elegant, fast, and works surprisingly well for text.

Real-world use: Gmail, Outlook — every major email client uses some form of Bayesian spam filtering. It was one of the first ML successes in production, deployed in the early 2000s.
📧 Naive Bayes • Card 17 of 44
📐 Bayes' Theorem — The Math Behind the Magic

Bayes' theorem tells us how to update our beliefs based on new evidence. For classification:

P(Class | Data) = P(Data | Class) × P(Class) / P(Data)

In plain English:

  • 🎯 P(Class | Data) — Given what we see in the email, how likely is it spam? (what we want)
  • 📊 P(Data | Class) — How likely is this pattern of words in spam emails? (from training data)
  • 📈 P(Class) — Overall fraction of emails that are spam (the prior)
  • 📉 P(Data) — Same for both classes; we can ignore it for comparison
Key insight: We pick the class that maximizes P(Data|Class) × P(Class). We compare spam vs not-spam and declare whichever is bigger as the prediction.
📧 Naive Bayes • Card 18 of 44
🙈 The "Naive" Assumption — Why It's Called That

To make computation easy, Naive Bayes makes a bold simplifying assumption:

All features are CONDITIONALLY INDEPENDENT given the class.

P(w₁,w₂,...,wₙ | spam) = P(w₁|spam) × P(w₂|spam) × ... × P(wₙ|spam)

In reality, words in an email are obviously NOT independent — "free" and "money" often appear together. This assumption is naive (unrealistic).

But here's the miracle: it still works incredibly well in practice! Even with this false assumption, the predictions are usually correct.

Why does this matter? Without the independence assumption, you'd need to count every combination of words across all spam emails — computationally impossible. The naive assumption turns an exponential problem into a linear one.

📧 Naive Bayes • Card 20 of 44
🔧 Laplacian Correction — Fixing the Zero Problem

Suppose the word "bitcoin" never appeared in any training spam email. Then:

P("bitcoin" | spam) = 0

But then multiplying by zero wipes out the entire probability — no matter how many other spam words appear, the result is zero. That's wrong!

Laplace Smoothing (add-one smoothing) fixes this: add 1 to every word count before computing probabilities.

P(wᵢ | class) = (count(wᵢ, class) + 1) / (count(class) + |vocabulary|)

This ensures no probability is exactly zero, even for unseen words.

Why does this matter? Without this fix, a single unseen word would make Naive Bayes completely non-functional. Always apply Laplace smoothing in practice.

🏘️ k-Nearest Neighbor • Card 22 of 44
🗳️ You Are Who You Hang Out With

Imagine you move to a new neighborhood and you don't know if it's a vegetarian-friendly area or not. You ask your 5 nearest neighbors:

🥗 Neighbor 1: Vegetarian   🍖 Neighbor 2: Not   🥗 Neighbor 3: Vegetarian   🥗 Neighbor 4: Vegetarian   🍖 Neighbor 5: Not

Majority vote: 3 vegetarians vs 2 not → the model predicts you're probably vegetarian too!

k-NN (k-Nearest Neighbors) does exactly this. For any new data point, look at the k closest training points and vote on the label.

Why does this matter? k-NN requires NO training phase — it just stores all training data and does computation at prediction time ("lazy learning"). Simple and effective, especially for low-dimensional data.
🏘️ k-Nearest Neighbor • Card 23 of 44
⚙️ The k-NN Algorithm — Step by Step

Given a new data point to classify:

  • Step 1: Compute the distance from the new point to every single training point. (Common: Euclidean distance = straight-line distance).
  • Step 2: Find the k closest training points (the k nearest neighbors).
  • Step 3: Take a majority vote among their labels → that's the prediction.
d(x,y) = √[(x₁−y₁)² + (x₂−y₂)² + ... + (xₙ−yₙ)²]

No model is built — at prediction time, you do all the work. This is why k-NN is called a lazy learner.

Gotcha: Because we compute distances, ALL features must be on the same scale! Always normalize/standardize features before using k-NN.

⚖️ Precision vs Recall — The Trade-off

Two of the most important metrics for imbalanced problems:

Precision = TP / (TP + FP)   |   Recall = TP / (TP + FN)
  • 🎯 Precision: "When I say positive, how often am I right?" — Measures false alarm rate. High precision = few false alarms.
  • 🔍 Recall (Sensitivity): "Of all actual positives, how many did I catch?" — Measures how many true cases are found. High recall = few misses.

Usually, boosting one lowers the other. If you lower the threshold (classify more things as positive), you catch more true cases (high recall) but also get more false alarms (lower precision).

F1-Score = 2 × (Precision × Recall) / (Precision + Recall)
F1 score: The harmonic mean of precision and recall. Use it when both matter equally and classes are imbalanced.
📏 Model Evaluation • Card 30 of 44
📈 ROC Curves — The Threshold Story

A classifier usually outputs a probability score, not just "yes" or "no". You choose a threshold (e.g., 0.5) to convert the score into a label.

If you lower the threshold → more things are classified as positive → higher recall, but also higher false positive rate.

The ROC Curve (Receiver Operating Characteristic) plots:

  • Y-axis: True Positive Rate (Recall) — want this HIGH
  • X-axis: False Positive Rate — want this LOW

As you sweep the threshold from 1 to 0, you trace out the curve. The AUC (Area Under the Curve) summarizes it in one number: 1.0 = perfect, 0.5 = random guessing.

When to use ROC: When comparing multiple classifiers and you want to see which one is best regardless of threshold choice. Great for imbalanced datasets.

🌲 Ensemble Methods • Card 33 of 44
👨‍⚕️ The Panel of 100 Doctors

One doctor's diagnosis might be wrong — they might be tired, biased, or just have a bad day. But if you get a second opinion from 100 doctors who independently examine the same patient, their majority vote is far more reliable.

This is the core idea of ensemble methods: combine many "weak" models (each slightly different, each making different kinds of errors) into one "strong" model. Their errors cancel out!

Think of it like the stock market — many individual investors may be wrong, but the market consensus (aggregated view) is often more accurate than any individual.

Why does this work? If each model makes uncorrelated errors, combining them reduces error dramatically. The key insight: models must be diverse — different errors, not the same error together.
🌲 Ensemble Methods • Card 34 of 44
🎒 Bagging — Bootstrap AGGregation

Bagging creates diversity by training each model on a different sample of the data:

  • 📦 Take your training set of N examples.
  • 🎲 For each of K models: randomly sample N examples with replacement (bootstrap). Some examples appear multiple times; some not at all.
  • 🌳 Train a separate model on each bootstrap sample.
  • 🗳️ Final prediction = majority vote (classification) or average (regression) of all K models.

Because each model sees a slightly different dataset, they make different errors. Averaging them out reduces variance — makes predictions more stable.

When to use: Bagging works best when individual models have high variance (like deep decision trees). It tames unstable, noisy models.
🌲 Ensemble Methods • Card 35 of 44
🚀 Boosting & AdaBoost — Learning from Mistakes

While Bagging trains models independently in parallel, Boosting trains them sequentially — each model focuses on where the previous one failed.

  • 🔁 Train Model 1. Find which examples it got wrong.
  • ⬆️ Upweight the misclassified examples (give them more importance).
  • 🏋️ Train Model 2 on the reweighted data. It focuses on hard cases.
  • 🔄 Repeat. Final prediction = weighted vote of all models (better models get higher weights).

AdaBoost (Adaptive Boosting) is the classic algorithm. Later: Gradient Boosting, XGBoost — state of the art on tabular data competitions.

Key difference from Bagging: Boosting targets BIAS (the model is systematically wrong). Bagging targets VARIANCE (the model is inconsistent). Boosting can overfit if pushed too far.
🌲 Ensemble Methods • Card 36 of 44
🌳 Random Forest — Bagging + Feature Randomness

Random Forest is an ensemble of decision trees with two layers of randomness:

  • 🎲 Bootstrap sampling: Each tree gets a different random sample of training data (like Bagging).
  • 🎯 Feature randomness: At each split, only a random subset of features is considered. This decorrelates the trees more than Bagging alone!

Why? If one feature is very strong (dominates all trees), all trees would be similar and make correlated errors. By randomly excluding features, each tree learns different aspects of the data.

🌱🌲🌳🌲🌱🌳 → 🏆
In practice: Random Forest is one of the most reliable algorithms — works well out of the box with minimal tuning, handles missing data, and provides feature importance scores. Often the first thing to try for tabular data.

📉 Logistic Regression • Card 38 of 44
🎯 Logistic Regression — Probabilities, Not Just Labels

Logistic regression doesn't directly predict a class — it predicts the probability of belonging to a class. Then you threshold (e.g., if P > 0.5, predict "Yes").

It uses the sigmoid function to squeeze any real number into a valid probability (0 to 1):

σ(z) = 1 / (1 + e⁻ᶻ)   where   z = w₀ + w₁x₁ + w₂x₂ + ...

The S-shaped sigmoid curve: as z → −∞, output → 0; as z → +∞, output → 1; at z=0, output = 0.5.

Why use it? Simple, fast, interpretable. Coefficients tell you the effect of each feature. Works well as a strong baseline before trying complex models.

📐 Mathematical Appendix
H(D) = −Σᵢ pᵢ log₂(pᵢ)

Where pᵢ is the proportion of examples in class i. H=0 when all examples belong to one class. H is maximized when all classes are equally likely. For binary classification with P(Yes)=p: H = −p log₂p − (1−p) log₂(1−p). Log base 2 gives entropy in bits.

Gini(D) = 1 − Σᵢ pᵢ²

For binary: Gini = 2p(1−p). Maximum impurity (Gini=0.5) when p=0.5. Pure node (Gini=0) when p=0 or p=1. CART uses Gini impurity for splitting decisions.

GainRatio(D,A) = IG(D,A) / SplitInfo(A)
SplitInfo(A) = −Σⱼ (|Dⱼ|/|D|) × log₂(|Dⱼ|/|D|)

Information Gain is biased towards attributes with many values. Gain Ratio penalizes attributes that split into many small branches. C4.5 (successor to ID3) uses Gain Ratio to correct this bias.

P(A|B) = P(B|A) × P(A) / P(B)

Derived from the definition of conditional probability: P(A|B) = P(A∩B)/P(B) and P(B|A) = P(A∩B)/P(A). Therefore P(A∩B) = P(A|B)P(B) = P(B|A)P(A). For classification, B is the observed data, A is the class. P(B) = Σ P(B|Aᵢ)P(Aᵢ) by total probability.

χ² = (|FP_A − FP_B| − 1)² / (FP_A + FP_B)

To compare two classifiers statistically, use McNemar's test on a contingency table of their errors. Significant result (p < 0.05) means the classifiers differ significantly. For continuous performance metrics across cross-validation folds, use a paired t-test: t = (mean_diff) / (std_diff / √n), with n−1 degrees of freedom.

📚 Complete Lecture & Research Foundations

🌲 Scalable Decision Trees: RainForest & BOAT

• RainForest Framework (Gehrke, Ramakrishnan, Ganti VLDB 1998): Bridges the gap between scalability and tree quality. Rather than loading the database into memory, it maintains an in-memory AVC-set (Attribute-Value, Classlabel counts) for each candidate attribute. The AVC-group is orders of magnitude smaller than the training data, allowing trees to scale to millions of tuples without sacrificing accuracy.

• BOAT (Bootstrapped Optimistic Algorithm for Tree Construction): Uses statistical bootstrapping to draw several small samples of the database, builds trees on each sample, and synthesizes an optimistic tree with confidence intervals. Constructs the exact tree in only 2 database scans.

• Tree Pruning: Prepruning (halts tree expansion early if impurity decrease falls below a threshold) vs. Postpruning (grows the complete tree and removes branches using cost-complexity pruning or pessimistic pruning on validation data).

📐 Naive Bayes Continuous Attributes & Laplacian Correction

• Continuous Attributes (Gaussian / Normal Distribution): When an attribute $X$ is continuous, compute sample mean $\mu_{ci}$ and standard deviation $\sigma_{ci}$ for class $c_i$. The probability density is given by:
$P(X = x | c_i) = \frac{1}{\sqrt{2\pi}\sigma_{ci}} e^{-\frac{(x - \mu_{ci})^2}{2\sigma_{ci}^2}}$.

• Laplacian Correction (Laplace Smoothing): If a word or attribute value never appears in a class, $P(A_k | C_i) = 0$, wiping out the entire probability product. To prevent this, add 1 to the numerator and $q$ (the number of possible values) to the denominator:
$P(A_k = v | C_i) = \frac{\text{count}(A_k = v, C_i) + 1}{\text{count}(C_i) + q}$.

🛋️ Lazy vs. Eager Learners & Case-Based Reasoning (CBR)

• Eager Learning: Constructs a comprehensive generalization model (e.g., Decision Tree, Neural Net) from training data before receiving test queries. Fast prediction time, high training time.

• Lazy Learning (Instance-Based): Stores training tuples as-is and defers model building until an unseen test tuple arrives. Zero training time, slow prediction time. Example: $k$-Nearest Neighbor ($k$-NN).

• Bias-Variance Tradeoff in $k$-NN: Small $k$ (e.g., $k=1$) is sensitive to noise/outliers (high variance, overfitting). Large $k$ brings in tuples from other classes (high bias, underfitting).

• Case-Based Reasoning (CBR): Differs from $k$-NN by storing complex, symbolic, structural case descriptions (e.g., legal court rulings or medical patient case histories) rather than points in Euclidean space, solving new problems by retrieving and adapting past cases.

📈 Linear Classifiers, Perceptron & Logistic Regression

• Decision Boundaries: Decision trees produce axis-aligned (hyperrectangular) decision boundaries. Linear classifiers find linear hyperplanes separating classes.

• Perceptron: Linear threshold neuron: $y = \text{sign}(W \cdot X + b)$. Updates weights iteratively when misclassifications occur.

• Logistic Regression: Models the posterior probability $P(Y=1|X)$ using the nonlinear Sigmoid function:
$P(Y=1|X) = \frac{1}{1 + e^{-(W \cdot X + b)}}$. Parameters are optimized using Maximum Likelihood Estimation (MLE).

📊 Classifier Comparison: Paired Student's t-Test & ROC/AUC Curves

• Comparing Two Classifiers ($M_1$ vs. $M_2$): Run 10-fold cross-validation. Compute the difference in error rates $d_i = \text{err}(M_1)_i - \text{err}(M_2)_i$ for each fold. Compute sample mean $ar{d}$ and standard deviation $s_d$. The test statistic is:
$t = \frac{ar{d}}{s_d / \sqrt{k}} \sim t_{k-1}$. If $|t| > t_{\text{critical}}$, we reject the null hypothesis and conclude that the performance difference is statistically significant.

• ROC Curves: Plots True Positive Rate (Sensitivity / Recall) on the Y-axis against False Positive Rate ($1 - \text{Specificity}$) on the X-axis across all decision thresholds. A random guess gives the diagonal line ($\text{AUC} = 0.5$); a perfect classifier has $\text{AUC} = 1.0$.

🤝 Deep-Dive into Ensembles & Class Imbalance

• AdaBoost (Adaptive Boosting): Assigns initial weights $w_i = 1/d$ to all tuples. In each round, trains a base classifier $M_i$. Its error rate is $\epsilon_i = \sum w_k \mathbb{I}(M_i(x_k) eq y_k)$. Classifier weight is $lpha_i = \frac{1}{2}\ln\frac{1-\epsilon_i}{\epsilon_i}$. Correctly classified tuples have weights decreased; misclassified tuples have weights increased. Final prediction is a weighted vote.

• Gradient Boosting & XGBoost: Fits each subsequent tree to the negative gradient (pseudo-residuals) of the loss function, optimizing both loss and tree complexity regularization.

• Random Forest: Uses bagging plus random feature selection at each node split (`Forest-RI` and `Forest-RC`), preventing dominant features from dominating all trees.

• Handling Class Imbalance: In rare-event detection (fraud, rare diseases), standard accuracy is deceptive. Techniques: (1) Oversampling (replicating rare cases or generating synthetic samples via SMOTE); (2) Undersampling majority class; (3) Threshold-moving; (4) Cost-sensitive learning.
