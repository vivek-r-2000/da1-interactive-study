A Primitive Operator for Similarity Joins

Surajit Chaudhuri, Venkatesh Ganti, Raghav Kaushik (VLDB 2006)

⏱️ Focus: 15:00
1. Relational Fuzzy Matching Dilemma

Joining Tables When Strings Don't Match Exactly

In relational databases, joins rely on strict equality: R.Customer = S.Customer. But when merging company databases, human errors and abbreviations make exact joins fail:

🏢 Real-World Examples: • "Microsoft Corporation" vs "Microsoft Corp."
• "ACM SIGMOD Conf 2006" vs "2006 Conf SIGMOD ACM"

A naive fuzzy join compares every pair of strings using Edit Distance or Jaccard. If both tables have 1,000,000 rows, that requires $10^{12}$ comparisons—taking weeks!

Surajit Chaudhuri, Venkatesh Ganti, and Raghav Kaushik (VLDB 2006) at Microsoft Research invented Prefix Filtering, creating a fast primitive operator for relational engines.
2. Mathematical Formalism

The Prefix Filtering Lemma

Strings are broken into tokens or $q$-grams (e.g. 3-letter substrings). Tokens are ordered globally by frequency (rarest token first).

The Prefix Filtering Property:
Let strings X and Y be represented as sorted token sets. To have Jaccard similarity ≥ θ:
Required Overlap c = ⌈θ / (1 + θ) × (|X| + |Y|)⌉

Prefix Length Equation:
Prefix_Length(X) = |X| - ⌈θ × |X|⌉ + 1

The Golden Lemma:
If X and Y have Jaccard similarity ≥ θ, their sorted prefixes of length Prefix_Length MUST share at least ONE common token! If their prefixes share no token, they CANNOT be similar—prune them instantly without computing full distance!
⚡ Length Filtering: Before checking tokens, check lengths! If $|Y| < \theta \times |X|$, string $Y$ is too short to ever meet the similarity threshold. Discard immediately with zero token checks!

4. Active Retention Quiz

Test Your Understanding

1. Why are tokens ordered globally by rarity (least frequent first) in prefix filtering?

Explanation: Correct! If we indexed common words like 'the' or 'inc', millions of candidates would be generated. Rare tokens maximize index selectivity.

2. If string X has 10 tokens and similarity threshold is θ = 0.8, what is its prefix length?

Explanation: Correct! Only the first 3 tokens need to be checked in the inverted index.

3. What is Length Filtering?

Explanation: Correct! Length filtering requires zero string inspections and prunes up to 70% of pairs upfront.

4. Does Prefix Filtering ever produce False Negatives (miss true matches)?

Explanation: Correct! It is an exact filtering lemma: zero false negatives guaranteed.

5. What distance measures can be accelerated with prefix filtering?

Explanation: Correct! Chaudhuri et al. generalize prefix filtering across set overlap, Jaccard, Cosine, and string edit distance.
