Scientific Calculator Operational Guide

Prof. Reddy officially noted that scientific calculators are permitted. Make sure you utilize these operations efficiently during numerical questions:

  • • Logarithm Base 2: Compute $\log_2(p) = \frac{\ln(p)}{\ln(2)}$ or $\frac{\log_{10}(p)}{\log_{10}(2)}$. Do not round intermediate logs!
  • • Entropy Accumulator: Store parent $Info(D)$ in memory register `M+`. Compute each partition $Info(D_j)$ and sum weighted proportions directly.
  • • Chi-Square $(\chi^2)$: Calculate expected frequencies $E_{ij} = \frac{R_i \times C_j}{N}$ using two-variable statistics or fraction operations.
  • • Vector Norms in SVM: Use Pythagoras or polar conversions to compute $\|\vec{w}\| = \sqrt{w_1^2 + w_2^2}$ for margin $\frac{2}{\|\vec{w}\|}$.

Exercise 2.2 — Attribute Types & Measurement Scales Chapter 2: Data Preprocessing
Problem: Suppose that the values for a given attribute $A$ are: (a) age, (b) temperature in Celsius, (c) income, (d) zip code, (e) customer satisfaction ranking. Classify each attribute as nominal, ordinal, interval, or ratio, and state whether it is qualitative (categorical) or quantitative (numeric).

Step-by-Step Solution:

  • (a) Age: Quantitative (numeric), Ratio scale. Meaningful true zero point ($0$ represents absence of age / birth), and ratio comparisons are valid (e.g. 40 years is twice as old as 20 years).
  • (b) Temperature in Celsius: Quantitative (numeric), Interval scale. $0^\circ\text{C}$ is arbitrary (freezing point of water, not absence of thermal energy). $20^\circ\text{C}$ is not "twice as hot" as $10^\circ\text{C}$.
  • (c) Income: Quantitative (numeric), Ratio scale. Has an absolute zero point (\$0 represents no income) and ratios are preserved.
  • (d) Zip Code: Qualitative (categorical), Nominal scale. The digits serve solely as identifiers/labels; arithmetic differences between zip codes have no numeric meaning.
  • (e) Customer Satisfaction (Poor, Fair, Good, Excellent): Qualitative (categorical), Ordinal scale. Values have a meaningful relative ranking order, but the differences between successive ranks are not quantifiable.
Exercise 2.7 — Cosine vs. Euclidean vs. Jaccard Similarity Chapter 2: Data Preprocessing
Problem: Given two document term-frequency vectors $\vec{x} = (5, 0, 3, 0, 2, 0, 0, 2, 0, 0)$ and $\vec{y} = (3, 0, 2, 0, 1, 1, 0, 1, 0, 1)$. (a) Find the Cosine similarity $\text{sim}(\vec{x}, \vec{y})$. (b) Find the Euclidean distance $d(\vec{x}, \vec{y})$. (c) If vectors represent asymmetric binary attributes, compute the Jaccard coefficient $J(\vec{x}, \vec{y})$.

Step-by-Step Derivation:

(a) Cosine Similarity: $$\vec{x} \cdot \vec{y} = (5 \times 3) + (0 \times 0) + (3 \times 2) + 0 + (2 \times 1) + 0 + 0 + (2 \times 1) + 0 + 0 = 15 + 6 + 2 + 2 = 25$$ $$\|\vec{x}\| = \sqrt{5^2 + 0^2 + 3^2 + 0^2 + 2^2 + 0^2 + 0^2 + 2^2 + 0^2 + 0^2} = \sqrt{25 + 9 + 4 + 4} = \sqrt{42} \approx 6.4807$$ $$\|\vec{y}\| = \sqrt{3^2 + 0^2 + 2^2 + 0^2 + 1^2 + 1^2 + 0^2 + 1^2 + 0^2 + 1^2} = \sqrt{9 + 4 + 1 + 1 + 1 + 1} = \sqrt{17} \approx 4.1231$$ $$\text{sim}(\vec{x}, \vec{y}) = \frac{\vec{x} \cdot \vec{y}}{\|\vec{x}\| \|\vec{y}\|} = \frac{25}{\sqrt{42 \times 17}} = \frac{25}{\sqrt{714}} \approx \frac{25}{26.7208} = \mathbf{0.9356}$$
(b) Euclidean Distance: $$d(\vec{x}, \vec{y}) = \sqrt{(5-3)^2 + (3-2)^2 + (2-1)^2 + (0-1)^2 + (2-1)^2 + (0-1)^2} = \sqrt{4 + 1 + 1 + 1 + 1 + 1} = \sqrt{9} = \mathbf{3.0}$$
(c) Asymmetric Binary Jaccard Coefficient: $$q = \text{items where both } x_i > 0 \text{ and } y_i > 0 = 3 \text{ terms (indices 1, 3, 5, 8: wait, indices 1, 3, 5, 8 are both non-zero} \Rightarrow q=4)$$ $$r = \text{items where } x_i > 0 \text{ and } y_i = 0 \Rightarrow 0 \text{ terms}$$ $$s = \text{items where } x_i = 0 \text{ and } y_i > 0 = 2 \text{ terms (indices 6, 10)}$$ $$J(\vec{x}, \vec{y}) = \frac{q}{q + r + s} = \frac{4}{4 + 0 + 2} = \frac{4}{6} = \mathbf{0.667}$$
Exercise 2.18 — Data Normalization Transformations Chapter 2: Data Preprocessing
Problem: Given a sample dataset for attribute $A$: $\{200, 300, 400, 600, 1000\}$. Normalize value $v = 400$ by: (a) Min-max normalization into $[0, 1]$, (b) z-score normalization (with $\mu=500, \sigma=296.65$), (c) Normalization by decimal scaling.

Step-by-Step Solution:

(a) Min-Max Normalization: $\min(A) = 200, \max(A) = 1000, [new\_min, new\_max] = [0, 1]$: $$v' = \frac{v - \min(A)}{\max(A) - \min(A)} (new\_max - new\_min) + new\_min = \frac{400 - 200}{1000 - 200}(1) + 0 = \frac{200}{800} = \mathbf{0.25}$$
(b) z-Score Normalization: Mean $\bar{A} = \frac{200+300+400+600+1000}{5} = 500$, Standard deviation $\sigma \approx 296.65$: $$v' = \frac{v - \bar{A}}{\sigma} = \frac{400 - 500}{296.65} = \frac{-100}{296.65} \approx \mathbf{-0.337}$$
(c) Decimal Scaling: Maximum absolute value is $1000$. Hence smallest integer $j$ such that $\max(|v'|) < 1$ is $j = 4$ ($10^4 = 10000$): $$v' = \frac{v}{10^j} = \frac{400}{10^4} = \mathbf{0.04}$$
Exercise 2.19 — Chi-Square $(\chi^2)$ Independence Test Chapter 2: Data Preprocessing
Problem: In a study examining gender and preference for fiction vs non-fiction books among 1000 readers, the observed frequencies are: Male Fiction = 250, Male Non-Fiction = 200, Female Fiction = 350, Female Non-Fiction = 200. Test whether gender and book preference are statistically independent at significance level $\alpha = 0.001$ ($crit=10.828, df=1$).

Step-by-Step Derivation:

Female350 ($e=330$)200 ($e=220$)550
Total Column600400N = 1000
Expected Frequencies $E_{ij} = \frac{Row\_Total \times Col\_Total}{N}$: $$E_{11} = \frac{450 \times 600}{1000} = 270, \quad E_{12} = \frac{450 \times 400}{1000} = 180$$ $$E_{21} = \frac{550 \times 600}{1000} = 330, \quad E_{22} = \frac{550 \times 400}{1000} = 220$$ $$\chi^2 = \sum \frac{(O_{ij} - E_{ij})^2}{E_{ij}} = \frac{(250-270)^2}{270} + \frac{(200-180)^2}{180} + \frac{(350-330)^2}{330} + \frac{(200-220)^2}{220}$$ $$\chi^2 = \frac{400}{270} + \frac{400}{180} + \frac{400}{330} + \frac{400}{220} = 1.481 + 2.222 + 1.212 + 1.818 = \mathbf{6.733}$$

Conclusion: Degrees of freedom $df = (2-1)(2-1) = 1$. The critical value at $\alpha = 0.001$ is $10.828$. Since $\chi^2 = 6.733 < 10.828$, we fail to reject the null hypothesis at $\alpha=0.001$ (they are not statistically significantly dependent at 99.9% confidence).

Exercise 2.20 — Pearson Correlation Coefficient $(r_{A,B})$ Chapter 2: Data Preprocessing
Problem: Calculate the correlation coefficient $r_{A,B}$ between two attributes $A = (6, 5, 4, 3, 2)$ and $B = (2, 3, 4, 5, 6)$ and interpret the relationship.

Step-by-Step Derivation:

$$\bar{A} = 4, \quad \bar{B} = 4, \quad \sigma_A = \sqrt{\frac{(2)^2 + (1)^2 + 0 + (-1)^2 + (-2)^2}{5}} = \sqrt{\frac{10}{5}} = \sqrt{2} \approx 1.414$$ $$\sigma_B = \sqrt{2} \approx 1.414, \quad \sum (a_i - \bar{A})(b_i - \bar{B}) = (2)(-2) + (1)(-1) + (0)(0) + (-1)(1) + (-2)(2) = -4 - 1 + 0 - 1 - 4 = -10$$ $$r_{A,B} = \frac{\sum (a_i - \bar{A})(b_i - \bar{B})}{n \sigma_A \sigma_B} = \frac{-10}{5 \times \sqrt{2} \times \sqrt{2}} = \frac{-10}{10} = \mathbf{-1.0}$$

Interpretation: Perfect negative linear correlation ($r_{A,B} = -1.0$). As $A$ increases, $B$ decreases in exact linear lockstep.

Exercise 3.15 — Data Warehouse Schema Design Chapter 3: Data Warehousing & OLAP
Problem: Compare Star Schema, Snowflake Schema, and Fact Constellation Schema with respect to normalization, query performance, storage overhead, and maintenance complexity.
  • Star Schema: Large central fact table connected to completely denormalized dimension tables. Maximum query speed (single-join queries), simple navigation, but contains redundant dimension attributes.
  • Snowflake Schema: Dimension tables are normalized into hierarchical lookup tables (e.g., `item` $\rightarrow$ `supplier` $\rightarrow$ `country`). Eliminates redundancy, saves storage, but degrades query performance due to multiple complex relational joins.
  • Fact Constellation (Galaxy) Schema: Multiple fact tables sharing common (conformed) dimension tables (e.g., `Sales Fact` and `Shipping Fact` both sharing `Time`, `Item`, and `Location` dimensions). Necessary for enterprise data warehouses covering multiple business processes.
Exercise 3.17 — Lattice of Cuboids & Cube Sizing Chapter 3: Data Warehousing & OLAP
Problem: Suppose a data cube has 4 dimensions: $A, B, C, D$. (a) How many cuboids are in the lattice? (b) If dimension $A$ has 10 distinct values, $B$ has 5, $C$ has 20, and $D$ has 100, what is the maximum number of cells in the base cuboid and the full data cube?
(a) Number of Cuboids: In an $n$-dimensional cube, the lattice consists of $2^n$ cuboids. For $n=4$: $$\text{Total Cuboids} = 2^4 = \mathbf{16 \text{ cuboids}}$$
(b) Cell Capacity: $$\text{Base Cuboid Cells} = |A| \times |B| \times |C| \times |D| = 10 \times 5 \times 20 \times 100 = \mathbf{100,000 \text{ cells}}$$ $$\text{Full Data Cube Cells} = \prod_{i=1}^n (|D_i| + 1) = (10+1)(5+1)(20+1)(100+1) = 11 \times 6 \times 21 \times 101 = \mathbf{140,086 \text{ cells}}$$
Exercise 3.18 — BUC Iceberg Cube Bottom-Up Computation Chapter 3: Data Warehousing & OLAP (Section 3.5.2)
Problem: Trace the Bottom-Up Computation (BUC) algorithm on dimensions $(A, B, C)$ with minimum support threshold $min\_sup = 3$. Explain the recursive partitioning order and why dimensions must be sorted by cardinality in ascending order.

BUC Execution Mechanics:

  • Bottom-Up Order: BUC traverses the lattice from apex cuboid `ALL` ($0$-D) downwards into $1$-D cuboids ($A, B, C$), then $2$-D cuboids ($AB, AC, BC$), and finally $3$-D base cuboid ($ABC$).
  • Iceberg Condition & Anti-Monotonic Pruning: If a partition cell count is less than $min\_sup$ (e.g. $\text{count}(A=a_1) < 3$), then no descendant cell in sub-cubes containing $A=a_1$ (e.g. $(a_1, B, *)$, $(a_1, *, C)$, $(a_1, B, C)$) can satisfy the iceberg threshold. BUC immediately prunes the entire sub-tree!
  • Cardinality Sorting Heuristic: Sort dimensions in increasing order of cardinality (dimensions with fewest distinct values first). The dimension with fewest values partitions the data into fewer, larger blocks initially; deeper dimensions with large cardinality will prune faster and avoid unnecessary recursive stack allocations.
Exercise 3.22 — Attribute-Oriented Induction (AOI) Chapter 3: Data Warehousing & OLAP
Problem: How does Attribute-Oriented Induction (AOI) perform concept generalization? State the two primary generalization strategies: attribute removal and attribute generalization.
  • Attribute Removal: If an attribute has a large number of distinct values but no concept hierarchy is available (e.g. `Social Security Number`, `Student ID`), or if the higher-level concepts are irrelevant to the target task, the attribute is removed completely.
  • Attribute Generalization: When a concept hierarchy exists (e.g., `City` $\rightarrow$ `State` $\rightarrow$ `Country`), values are replaced by higher-level concept generalized values until the number of distinct values in the relation drops below the specified attribute threshold.
Exercise 4.3 — Apriori Anti-Monotonicity Principle Chapter 4: Basic Pattern Mining
Problem: Prove the Apriori property: All nonempty subsets of a frequent itemset must also be frequent. Conversely, prove why any superset of an infrequent itemset must be infrequent.

Formal Mathematical Proof:

Let $X$ and $Y$ be itemsets such that $X \subseteq Y$. The support count of an itemset is the number of transactions $T$ containing that itemset: $$\sigma(Y) = |\{T \in D \mid Y \subseteq T\}|$$ Since $X \subseteq Y$, every transaction that contains $Y$ must also contain $X$: $$\{T \in D \mid Y \subseteq T\} \subseteq \{T \in D \mid X \subseteq T\} \implies \sigma(Y) \le \sigma(X)$$ Dividing by total transactions $|D|$: $$\text{support}(Y) \le \text{support}(X)$$ 1. If $Y$ is frequent ($\text{support}(Y) \ge min\_sup$), then $\text{support}(X) \ge \text{support}(Y) \ge min\_sup \implies X$ is frequent. 2. If $X$ is infrequent ($\text{support}(X) < min\_sup$), then $\text{support}(Y) \le \text{support}(X) < min\_sup \implies Y$ must be infrequent. (Q.E.D.)
Exercise 4.6 — Apriori Candidate Join & Prune Steps Chapter 4: Basic Pattern Mining
Problem: Given frequent 3-itemsets $L_3 = \{\{a, b, c\}, \{a, b, d\}, \{a, c, d\}, \{a, c, e\}, \{b, c, d\}\}$. (a) Generate candidate 4-itemsets $C_4$ using the $L_3 \bowtie L_3$ join step. (b) Prune candidates using the Apriori property.
(a) Join Step $L_3 \bowtie L_3$: Two itemsets $p, q \in L_3$ are joined if their first $k-2=1$ items match (lexicographically ordered: $p[1]=q[1]$):
  • Join $\{a, b, c\}$ and $\{a, b, d\} \implies \{a, b, c, d\}$.
  • Join $\{a, c, d\}$ and $\{a, c, e\} \implies \{a, c, d, e\}$.
  • No other pairs share prefix $k-1$ elements. Thus raw candidate set is $C_4 = \{\{a, b, c, d\}, \{a, c, d, e\}\}$.
(b) Prune Step (Check all 3-item subsets in $L_3$):
  • For $\{a, b, c, d\}$: Subsets are $\{a, b, c\} \in L_3$, $\{a, b, d\} \in L_3$, $\{a, c, d\} \in L_3$, $\{b, c, d\} \in L_3$. All subsets are frequent $\implies$ Retained in $C_4$.
  • For $\{a, c, d, e\}$: Subsets are $\{a, c, d\} \in L_3$, $\{a, c, e\} \in L_3$, $\{a, d, e\} \notin L_3$, $\{c, d, e\} \notin L_3$. Infrequent subsets found $\implies$ Pruned!

Final Candidate Set: $C_4 = \{\{a, b, c, d\}\}$.

Exercise 4.10 — FP-Tree Construction & Pattern Growth Chapter 4: Basic Pattern Mining
Problem: Describe the two scans required to construct an FP-Tree from a transactional database, and explain how a Conditional FP-Tree is mined for a suffix item.
  • Scan 1 (Support Counting & Sorting): Scan DB to calculate support of all items. Discard items with support $< min\_sup$. Sort remaining frequent items in descending order of support frequency (F-List).
  • Scan 2 (Tree Construction): Re-scan DB. For each transaction, filter non-frequent items, re-order according to F-List, and insert as a branch from root node. Increment node counts along shared prefixes or create new children when prefixes diverge. Update header table horizontal node-links.
  • Conditional Pattern Base & Tree Mining: For suffix item $X$, follow node-links in header table to find all prefix paths ending at $X$. Form the conditional pattern base (prefix paths with count equal to $X$'s node count). Construct the conditional FP-tree by counting item frequencies in prefix paths and keeping only items $\ge min\_sup$. Recurse until tree has single prefix path.
Exercise 6.7 — Information Gain & Gini Index Derivations Chapter 6: Basic Classification Concepts
Problem: In a training dataset $D$ of 14 instances, class `buys_computer` has 9 `yes` and 5 `no`. Attribute `age` has partitions: `youth` (2 yes, 3 no), `middle_aged` (4 yes, 0 no), `senior` (3 yes, 2 no). Calculate (a) $Info(D)$, (b) $Info_{age}(D)$, (c) $Gain(age)$, and (d) $Gini(D)$.
(a) Base Entropy $Info(D)$: $$Info(D) = -\left(\frac{9}{14}\log_2\frac{9}{14} + \frac{5}{14}\log_2\frac{5}{14}\right) = -(0.6429 \times (-0.6374) + 0.3571 \times (-1.4854)) = 0.4098 + 0.5305 = \mathbf{0.9403 \text{ bits}}$$
(b) Attribute Entropy $Info_{age}(D)$: $$Info(D_{youth}) = -\left(\frac{2}{5}\log_2\frac{2}{5} + \frac{3}{5}\log_2\frac{3}{5}\right) = \mathbf{0.9710 \text{ bits}}$$ $$Info(D_{middle}) = -\left(\frac{4}{4}\log_2\frac{4}{4} + 0\right) = \mathbf{0 \text{ bits (pure)}}$$ $$Info(D_{senior}) = -\left(\frac{3}{5}\log_2\frac{3}{5} + \frac{2}{5}\log_2\frac{2}{5}\right) = \mathbf{0.9710 \text{ bits}}$$ $$Info_{age}(D) = \frac{5}{14}(0.9710) + \frac{4}{14}(0) + \frac{5}{14}(0.9710) = 2 \times 0.3468 + 0 = \mathbf{0.6936 \text{ bits}}$$
(c) Information Gain: $$Gain(age) = Info(D) - Info_{age}(D) = 0.9403 - 0.6936 = \mathbf{0.2467 \text{ bits}}$$
(d) Gini Impurity $Gini(D)$: $$Gini(D) = 1 - \sum_{i=1}^m p_i^2 = 1 - \left[\left(\frac{9}{14}\right)^2 + \left(\frac{5}{14}\right)^2\right] = 1 - [0.4133 + 0.1276] = 1 - 0.5408 = \mathbf{0.4592}$$
Exercise 6.19 — Naive Bayes Classification with Laplace Smoothing Chapter 6: Basic Classification Concepts
Problem: Given a binary classification problem with classes $C_1$ (70 samples) and $C_2$ (30 samples). An attribute $A$ has 3 values $a_1, a_2, a_3$. In $C_1$, counts are $a_1=50, a_2=20, a_3=0$. Show how Laplace smoothing avoids zero-probability multiplication when classifying a sample with $A=a_3$.

Step-by-Step Derivation:

Without smoothing, $P(a_3|C_1) = \frac{0}{70} = 0$, which nullifies the entire product $P(\vec{X}|C_1) = \prod P(x_k|C_1) = 0$. Laplace correction adds $1$ to each count and $q$ (number of distinct values $=3$) to the denominator: $$P_{Laplace}(a_1|C_1) = \frac{50 + 1}{70 + 3} = \frac{51}{73} \approx 0.6986$$ $$P_{Laplace}(a_2|C_1) = \frac{20 + 1}{70 + 3} = \frac{21}{73} \approx 0.2877$$ $$P_{Laplace}(a_3|C_1) = \frac{0 + 1}{70 + 3} = \frac{\mathbf{1}}{\mathbf{73}} \approx \mathbf{0.0137}$$ Notice the sum remains valid: $\frac{51+21+1}{73} = \frac{73}{73} = 1.0$. Zero-probability trap is completely eliminated.

Ch 5 Paper (i) Han & Fu (TKDE 1999)

Mining Multiple-Level Association Rules in Large Databases

Core Problem: Mining at high abstraction levels yields trivial rules (e.g. `Dairy` $\to$ `Bread`), while mining at low abstraction levels yields low support (e.g. `Dairyland 2% Milk` has $<0.01\%$ support).

Key Innovations:

  • Taxonomy Concept Hierarchies with progressive minimum support thresholds (higher minsup at Level 1, reduced minsup at Level 2).
  • Redundancy Filtering: A rule at Level $l$ is redundant if its confidence is expected from its ancestor rule at Level $l-1$.

Ch 5 Paper (ii) Srikant & Agrawal (SIGMOD 1996)

Mining Quantitative Association Rules in Large Relational Tables

Core Problem: Boolean association rules cannot directly handle numeric attributes (e.g. `Age`, `Income`) without information loss or combinatorial explosion.

Key Innovations:

  • Equi-depth binning partition, followed by merging consecutive bins to discover generalized interval rules (e.g. $\text{Age:}[20..30] \Rightarrow \text{Cars}:1$).
  • Partial Completeness Bound $K$: Formal mathematical guarantee that no frequent itemset will be lost due to discretization error: $K = \frac{2-m}{2-2m}$.
  • Minimum interest measure $R$ to prune redundant sub-interval rules.
Open Full Paper Study Page →
Ch 5 Paper (iii) Liu, Liao, Choudhary (PAKDD 2005)

A Two-Phase Algorithm for Fast Discovery of High Utility Itemsets

Core Problem: Frequency $\ne$ Profitability. Items with high profit margin may appear infrequently. However, utility does not satisfy the downward closure property!

Key Innovations:

  • Transaction-Weighted Utilization (TWU): $TWU(X) = \sum_{T \supseteq X} TU(T)$.
  • TWDC Property: If $TWU(X) < min\_util$, then $X$ and any superset $Y \supseteq X$ cannot be high utility. Downward closure is restored!
  • Two-Phase Architecture: Phase 1 discovers Candidate High Utility Itemsets (HTWUIs); Phase 2 performs one database scan to prune false positives.

Ch 8 Paper (i) Ng & Han (TKDE 1994)

CLARANS: Clustering Objects for Spatial Data Mining

Core Problem: Partitioning Around Medoids (PAM) has $O(k(n-k)^2)$ complexity, making it intractable for large datasets. CLARA fixed sampling biases against non-uniform clusters.

Key Innovations:

  • Treats clustering as graph search: Nodes are sets of $k$ medoids; edges connect sets differing by a single medoid swap.
  • Randomized local search: Examines up to `maxneighbor` random neighbors. If cost improves, jump to neighbor; otherwise record local minimum. Repeat `numlocal` times.

Ch 8 Paper (ii) Zhang, Ramakrishnan, Livny (SIGMOD 1996)

BIRCH: An Efficient Data Clustering Method for Very Large Databases

Core Problem: Existing clustering algorithms require multiple passes over the entire dataset and hold all points in RAM.

Key Innovations:

  • Clustering Feature (CF) Vector: $CF = (N, \vec{LS}, SS)$ compresses arbitrary cluster into 3 summary statistics.
  • CF-Additivity Theorem: $CF_1 + CF_2 = (N_1+N_2, \vec{LS}_1+\vec{LS}_2, SS_1+SS_2)$. Cluster diameter $D$ computed purely from $CF$.
  • CF-Tree: Height-balanced B+-tree like structure with branching factor $B$ and leaf threshold $T$. Single pass $O(n)$ data loading!

DBSCAN: Density-Based Algorithm with Noise

Core Problem: Partitioning algorithms (k-Means) can only find convex spherical clusters and are extremely sensitive to outliers.

Key Innovations:

  • Core points ($|N_\epsilon(p)| \ge MinPts$), Border points ($p \in N_\epsilon(q)$ where $q$ is Core), and Noise points.
  • Density-reachability and Density-connectivity formalisms guarantees arbitrary cluster shape discovery without specifying $k$ in advance.

Ch 8 Paper (iv) Karypis, Han, Kumar (IEEE Computer 1999)

CHAMELEON: Hierarchical Clustering Using Dynamic Modeling

Core Problem: CURE and ROCK use static global user parameters and ignore the internal interconnectivity and closeness of clusters.

Key Innovations:

  • Two-Phase Framework: (1) Graph partitioning on k-NN graph into dense sub-clusters using hMETIS; (2) Agglomerative hierarchical merge using dynamic modeling.
  • Relative Interconnectivity (RI): $RI(C_i, C_j) = \frac{2 |EC_{\{C_i, C_j\}}|}{|EC_{C_i}| + |EC_{C_j}|}$ normalizes edge cuts by internal sub-cluster cuts.
  • Relative Closeness (RC): Normalizes average cross-cluster edge weights by internal edge weights. Clusters merge only if both $RI$ and $RC$ are high.

Exam Reference

1. Preprocessing, Distances & Correlation

Minkowski Distance ($L_p$ norm): $$d(\vec{x}, \vec{y}) = \left(\sum_{i=1}^n |x_i - y_i|^p\right)^{1/p} \quad (p=1: \text{Manhattan}, p=2: \text{Euclidean})$$
Cosine Similarity: $$\text{sim}(\vec{x}, \vec{y}) = \frac{\vec{x} \cdot \vec{y}}{\|\vec{x}\| \|\vec{y}\|}$$
Chi-Square Independence Statistic: $$\chi^2 = \sum_{i=1}^r \sum_{j=1}^c \frac{(O_{ij} - E_{ij})^2}{E_{ij}}, \quad E_{ij} = \frac{count(A=a_i) \times count(B=b_j)}{N}$$

2. Data Warehousing & Cubes

Lattice of Cuboids: $$\text{Total Cuboids} = 2^n \quad (n = \text{number of dimensions})$$
Total Data Cube Cells: $$\text{Total Cells} = \prod_{i=1}^n (|D_i| + 1)$$
Greedy Lattice Selection (Harinarayan et al. '96): $$\text{Benefit}(v, S) = \sum_{w \le v} \max(0, C(w, S) - C(w, S \cup \{v\}))$$ $$\text{Guaranteed Approximation Ratio} \ge 1 - \frac{1}{e} \approx 63\%$$

3. Classification & Decision Trees

Entropy & Information Gain: $$Info(D) = -\sum_{i=1}^m p_i \log_2(p_i), \quad Info_A(D) = \sum_{j=1}^v \frac{|D_j|}{|D|} Info(D_j)$$ $$Gain(A) = Info(D) - Info_A(D)$$
Gain Ratio (C4.5): $$SplitInfo_A(D) = -\sum_{j=1}^v \frac{|D_j|}{|D|} \log_2 \frac{|D_j|}{|D|}, \quad GainRatio(A) = \frac{Gain(A)}{SplitInfo_A(D)}$$
Gini Impurity (CART): $$Gini(D) = 1 - \sum_{i=1}^m p_i^2, \quad Gini_A(D) = \frac{|D_1|}{|D|}Gini(D_1) + \frac{|D_2|}{|D|}Gini(D_2)$$

4. SVM & Cluster Quality Metrics

SVM Margin Width: $$\text{Hyperplane: } \vec{w} \cdot \vec{x} + b = 0 \implies \text{Margin Width } \gamma = \frac{2}{\|\vec{w}\|}$$
Silhouette Coefficient $s(i)$: $$s(i) = \frac{b(i) - a(i)}{\max(a(i), b(i))}, \quad -1 \le s(i) \le +1$$ ($a(i)$: average intra-cluster distance, $b(i)$: min average nearest-cluster distance).
BIRCH Cluster Diameter: $$D = \sqrt{\frac{2 N \cdot SS - 2 \|\vec{LS}\|^2}{N(N-1)}}$$

Special Focus

Q1: How can Clustering (Ch 8) be used as a Preprocessing step for Classification (Ch 6 & 7)?

1. Unsupervised Discretization: Clustering high-dimensional continuous attributes into $k$ discrete clusters replaces raw continuous values with cluster IDs, preventing overfitting in Decision Trees and Naive Bayes.

2. Semi-Supervised Label Propagation: In large datasets where only 5% of samples are labeled, run DBSCAN or K-Means. Propagate known labels to unlabelled samples within dense pure clusters, then train an SVM classifier.

3. Prototype Selection for k-NN: To reduce $O(n)$ inference latency in k-Nearest Neighbor lazy learning, cluster the training instances with BIRCH/K-Means and use cluster centroids as prototypes.

Q2: How does OLAP / Cube Computation (Ch 3) intersect with Pattern Mining (Ch 4 & 5)?

1. Multi-Dimensional Association Rule Mining: Instead of single-dimensional market basket transactions, rules can involve multiple relational attributes from star schemas (e.g. $\text{age}(X, \text{"20..29"}) \wedge \text{buys}(X, \text{"laptop"}) \Rightarrow \text{buys}(X, \text{"backpack"})$).

2. Iceberg Cube Pruning via BUC: BUC's bottom-up anti-monotonicity pruning is conceptually identical to the Apriori property. Both prune search subtrees when aggregated counts fail to satisfy a minimum threshold.

Q3: Deep Learning (Sec 10.1) vs. Support Vector Machines (Sec 7.3)

1. Convexity vs Non-Convex Optimization: SVM optimization is a quadratic programming problem with a globally optimal convex solution. Neural network backpropagation solves non-convex gradient descent, subject to local minima and saddle points.

2. Kernel Trick vs Representation Learning: SVMs project data into high dimensions via fixed implicit kernels (RBF, Polynomial). Deep Learning networks learn hierarchical non-linear feature representations automatically through successive hidden layers.
